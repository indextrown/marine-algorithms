# 개발 계획

버전마다 모듈 하나를 C++ 코어 → C 다리층 → Swift 바인딩까지 끝내고 태그를 단다. 상태 없는 계산부터 시작해 상태 있는 객체(필터, 보간기)로 넘어간다.

기준값과 알고리즘은 공개 자료(논문, GeographicLib, 교재)에서만 가져온다. 회사 코드·기획서·설정값은 쓰지 않는다.

## 0.3 충돌 판단 `collision`

| 기능 | 내용 |
|---|---|
| CPA / TCPA | 두 선박의 위치·SOG·COG → 최근접 거리, 그때까지 시간 |
| 상대 운동 | 상대 속도·방위, 최근접 시점의 두 선박 위치 |

- 위치를 국지 평면(ENU)으로 바꿔 상대 운동을 푼다. 근거리 근사라는 점과 적용 거리 한계를 문서에 적는다.
- 경계 경우: 상대 속도 0(TCPA 정의 안 됨), 이미 최근접을 지남(TCPA < 0), 같은 위치.
- 위험 판정 임계값은 넣지 않는다. 쓰는 쪽이 CPA·TCPA로 판단한다.

## 0.4 운동 예측 `motion`

| 기능 | 내용 |
|---|---|
| 등속 직선 | 위치 + SOG + COG + 경과 시간 → 예측 위치 |
| 등속 선회 | 회전율(ROT)까지 넣어 원호를 따라 예측 |
| 예측 경로 | 일정 간격의 예측 위치 목록 |

- 상태 없는 함수로 둔다. 0.5의 필터와 0.6의 보간기가 이 함수를 쓴다.

## 0.5 칼만 필터 `filter`

| 기능 | 내용 |
|---|---|
| 선형 칼만 필터 | 작은 고정 크기 행렬, 예측·갱신 |
| 확장 칼만 필터(EKF) | CTRV(등속·등회전) 모델. 위치·SOG·COG 측정으로 회전율을 추정 |

- 처음으로 상태 있는 객체가 생긴다. C는 `ma_filter_new` / `_update` / `_free`, Swift는 `final class` + `deinit`.
- 수렴, 측정 누락, 시간 역전(과거 시각의 측정) 처리를 테스트한다.

## 0.6 위치 보간기 `interpolation`

| 기능 | 내용 |
|---|---|
| 측정 넣기 | 시각이 붙은 위치·SOG·COG |
| 지금 위치 묻기 | 임의 시각의 추정 위치·침로 |
| 부드러운 전환 | 새 측정이 들어와 예측과 어긋날 때 순간이동 대신 짧게 이어 붙인다 |

- 0.4 운동 예측과 0.5 필터를 묶는다. 화면 갱신 주기(60Hz)로 불러도 되는 성능을 목표로 한다.
